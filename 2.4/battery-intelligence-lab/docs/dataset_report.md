## 2. NASA 배터리 데이터 (A)

### 2.1 파일
- 바깥 ZIP 안에 ZIP 6개가 들어 있는 이중 구조이며, CRC 검사는 7개 ZIP 모두 통과했다.
- `.mat`은 모두 MATLAB v5 형식이라 `scipy.io.loadmat`으로 읽힌다.
- `2. BatteryAgingARC_25_26_27_28_P1.zip`과 `3. BatteryAgingARC_25-44.zip`에 B0025~B0028이 똑같이 들어 있다(SHA-256 동일). 그래서 한 번만 추출했다.
- 우선 대상인 B0005, B0006, B0007, B0018은 모두 `1. BatteryAgingARC-FY08Q4/`에 있다.
- B0035, B0037은 원본에 없다.

### 2.2 실제 구조 (README와 다른 점 포함)
`<ID>.cycle(i)`에는 `type`, `ambient_temperature`, `time`(MATLAB datevec), `data`가 들어 있다. 34개 파일 전체에서 확인한 `data` 필드는 다음과 같다.

| type | 사이클 수 | 실제 필드 |
|---|---:|---|
| charge | 2,815 | Voltage_measured, Current_measured, Temperature_measured, Current_charge, Voltage_charge, Time |
| discharge | 2,794 | Voltage_measured, Current_measured, Temperature_measured, **Current_load, Voltage_load**, Time, Capacity |
| impedance | 1,956 | Sense_current, Battery_current, Current_ratio, Battery_impedance, **Rectified_Impedance**, Re, Rct |

- README와 다른 점: 방전 사이클의 필드명은 `Current_charge/Voltage_charge`가 아니라 `Current_load/Voltage_load`이다. 임피던스 필드는 `Rectified_impedance`가 아니라 `Rectified_Impedance`이다.
- 임피던스 배열은 복소수(complex128)이고, `Re`와 `Rct`는 스칼라이다.
- 충전 사이클에는 Capacity 필드가 없다. 충전량이 필요하면 전류를 시간에 대해 적분해야 한다.

### 2.5 라벨 정의
- Capacity: 방전 사이클마다 측정된 방전 용량(Ah)이다.
- SOH는 데이터에 직접 들어 있지 않으며 아래 두 정의 중 하나로 계산한다. `nasa_discharge_capacity.csv`에 두 열을 모두 넣었다.
  - `soh_rated = Capacity / 2.0 Ah` (README의 정격용량 기준)
  - `soh_initial = Capacity / 첫 방전 용량`
- EOL: README 기준으로 B0005/6/7/18은 1.4 Ah(정격 대비 30 % 감소), B0033/34/36/38~40은 1.6 Ah(20 % 감소)이다.
- RUL = (EOL에 처음 도달한 방전 번호) − (현재 방전 번호). B0007은 EOL에 도달하지 않아 1.4 Ah 기준으로는 RUL 정답이 없다.

## 3. 실차 10대 (B, EV10)

### 3.1 실제 구조 — README의 컬럼 설명과 다름
- `BatPackdata.mat`은 **MATLAB v7.3(HDF5)** 형식이다. `scipy.io.loadmat`으로는 읽히지 않아 h5py로 읽는다.
- README는 "각 파일이 차량 하나"이고 `Time(s), Current(A), Voltage(V), Cell_max(V), Cell_mean(V), Temperature(°C), Charge_Capacity(Ah), SOC(%)` 컬럼이 있다고 설명한다. 실제 파일은 다음과 같다.

```
BatPackdata (10x1 struct)
├─ Veh      차량 번호 1..10
├─ Type     'NCM' (10대 모두)
├─ Cn       정격용량 (Ah)
├─ Ncell    직렬 셀 수
├─ SOH      SOH 라벨 (소수, 차량당 1개)
├─ SOC_OCV  (8~13)x2 표: [SOC 비율, 셀 OCV(V)]
└─ data
   ├─ Inf   충전 구간별 struct 배열 (차량당 3~11개)
   │        I_load(A, 충전이 음수), Q(구간 내 누적 Ah), Vmax(셀 최대전압), Vmean(셀 평균전압)
   └─ SOC   구간별 SOC 범위 문자열, 예 '0-9', '9-21'
```

- **없는 것: Time, Temperature, 샘플별 SOC, 팩 전압.** 시간 정보는 없지만 dQ·3600/|I|의 중앙값이 10대 모두 1.000 s여서, 1 Hz로 샘플링되었다고 판단할 수 있다.
- NaN 0개. 구간 안의 배열 길이는 모두 같다.

### 3.2 라벨 검증
| 차량 | Cn 파일/README | SOH 파일 | SOH README | ΣQ/Cn |
|---|---|---:|---:|---:|
| 1 | 234/234 | 94.30 | 94.30 | 0.9430 |
| 2 | 174/174 | 93.85 | 93.85 | 0.9385 |
| 3 | 100/100 | 78.91 | 78.91 | 0.7891 |
| 4 | 115/115 | 87.77 | 87.77 | 0.8777 |
| **5** | **147/174** | **97.31** | **82.21** | 0.9731 |
| 6 | 100/100 | 92.87 | 92.87 | 0.9287 |
| 7 | 110/110 | 96.98 | 96.98 | 0.9698 |
| 8 | 152/152 | 90.81 | 90.81 | **0.9068** |
| 9 | 150/150 | 101.71 | 101.71 | 1.0171 |
| 10 | 100/100 | 99.08 | 99.08 | 0.9908 |

- **SOH 라벨 = 전 구간 충전량 합 ΣQ ÷ Cn** (9대는 소수 셋째 자리까지 일치하고, 차량 8만 0.13 %p 차이). 즉 라벨은 별도의 방전 용량 시험이 아니라 이 충전 데이터 자체에서 계산된 값이다. 따라서 입력 특징에 전체 Q를 쓰면 정답이 새어 들어간다.
- **차량 5 불일치**: ΣQ = 143.04 Ah를 174로 나누면 82.21 %(README), 147로 나누면 97.31 %(파일)이다. 어느 정격값이 맞는지는 데이터만으로 판단할 수 없으므로, 분석할 때 두 값을 모두 기록하고 저자 확인이 필요한 항목으로 남긴다.
- 라벨은 **차량당 1개, 총 10개**뿐이다. 시간에 따른 SOH 변화는 없다.

### 3.3 이상값
- `Vmean > Vmax`인 샘플이 있는 구간이 56개 중 40개이고, 최대 차이는 33 mV이다. Vmax 분해능이 0.01 V라서 반올림(최대 5 mV)으로는 설명되지 않는다. 두 신호의 기록 시점이 어긋났을 가능성이 있다.
- 양(+)의 전류(방전 또는 회생) 샘플이 있는 구간이 15개이다.
- 구간 안에서 Q가 0.001 Ah 넘게 줄어드는 샘플이 있는 구간이 4개이다.

## 4. 실차 20대 (C, EV20)

### 4.1 실제 구조
`#N.csv` 20개, 각 704,958~856,192행. 실제 헤더는 다음과 같다.
```
(index), record_time, soc, pack_voltage (V), charge_current (A), max_cell_voltage (V),
min_cell_voltage (V), max_temperature (℃), min_temperature (℃), available_energy (kw), available_capacity (Ah)
```
- `record_time`은 `yyyymmddHHMMSS` 정수이다. 기간은 2019-07-22 ~ 2021-11-16(842~847일, 약 28개월)이다.
- 충전 중일 때만 기록되며 간격은 8 s(15대) 또는 10 s(5대)이다. 주행(방전) 데이터는 없다.
- `charge_current`는 충전이 음수이다. 양수 행은 20대 합계 34개이다.
- `available_capacity`, `available_energy`는 BMS가 계산한 잔여 용량과 잔여 에너지이다(측정된 용량 라벨이 아님).

### 4.2 무결성
- 결측값 0개(20대 모두). 시간순 정렬 정상.
- 타임스탬프 중복 36,923행 — 확인한 차량(#1, #3, #6)은 **모든 값이 같은 완전 중복**이다. 적분 시간 간격이 0이라 용량 계산에는 영향이 없지만, 전처리에서 제거한다.
- 물리 범위를 벗어난 값: 셀 전압 2.5~4.35 V 밖 38행, 전류 3행. 이 값들은 삭제하지 않고 개수만 기록했다.

### 4.3 용량 추출 (`capacity_extract.py` 분석)
- 원본 스크립트는 `pyGPs`, `natsort`, `seaborn`을 import하고, 현재 SciPy에서 제거된 `scipy.integrate.trapz`를 쓰며, `..\vehicles\` 경로를 가정한다. 그래서 그대로는 실행되지 않으며, **실행하지 않고 로직만 `src/data/ev20.py`에 다시 구현했다.**
- 로직: 기록 간격이 10 s를 넘으면 세션을 나누고(100행 이상인 세션만 사용), SOC가 한 번에 +2 % 넘게 뛰거나 −0.1 % 넘게 떨어지는 세션은 제외한다. **용량 = ∫I dt / ΔSOC × 100**.
- 원본과 다른 점: 원본은 전류 결측(10 % 이하)을 앞의 값으로 채운다. 이 프로젝트는 값을 채우지 않는 원칙에 따라 결측이 있는 세션의 용량을 NaN으로 둔다. 실제로는 결측이 0개라 결과에는 차이가 없다.
- 결과: 세션 54,921개 → 원본 필터 통과 54,295개 → ΔSOC ≥ 30 % 세션 14,192개.
- ΔSOC ≥ 30 % 세션 용량의 분포: 1 % 분위 110.4, 중앙값 126.0, 99 % 분위 136.5 Ah. 최솟값 11.4 Ah 같은 이상값도 남아 있어 추가 필터가 필요하다.
- 차량별 첫 3개월 → 마지막 3개월 중앙값: 131.9~134.1 Ah → 109.1~118.3 Ah, **감소율 10.7~18.4 %(중앙값 13.4 %)**.
- 주의: 이 용량은 **BMS가 추정한 SOC에 의존하는 추정치**이며, 실험실에서 측정한 용량이 아니다. 공칭 145 Ah 대비 비율(마지막 3개월 0.75~0.82)을 SOH라고 부르려면 이 한계를 함께 적어야 한다.

NASA 셀의 SOH(측정 방전 용량 기준), EV10 SOH(충전량 기준), EV20 용량 추정치(BMS-SOC 기준)는 정의가 서로 다르다. 같은 축에 놓고 비교할 때는 반드시 이를 명시한다.

## 7. 다음 구현 순서
1. 전처리: EV20 완전 중복 행 제거와 이상 세션 규칙 확정. NASA 이상 셀과 0 Ah 사이클 처리 규칙 확정. `data/processed/`에 parquet 또는 csv로 저장.
2. NASA 특징 추출: 충전 CC 구간 시간, 전압창 충전량, dQ/dV 피크, 방전 온도 피크, Re/Rct.
3. NASA SOH 회귀 기준선: 선형, RF, XGBoost를 셀 단위로 나눠 검증(leave-one-cell-out)하고 MAE/RMSE로 비교.
4. NASA RUL: 용량 이력 기반 회귀 또는 시계열 외삽(B0005/6/18).
5. EV20 용량 추세: 월별 중앙값, 경과일·누적 충전량 대비 감소율, knee 후보 탐지.
6. 도메인 간 특징 정규화(전압창, 공칭용량 정규화) 후 NASA→EV10 적용 평가와 보정.
7. 문서화: 결과표, 한계, 차량 5 라벨 문의.
