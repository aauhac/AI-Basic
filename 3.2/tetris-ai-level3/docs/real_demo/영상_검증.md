# 실제 플레이 시연 영상: 제작 방식과 검증

- 영상 파일: `테트리스_레벨3_실제플레이_시연영상.mp4`

| 항목 | 값 |
|---|---|
| 길이 · 해상도 | 3분 39초 (219.0초) · 1920×1080 · 30fps · H.264(High, yuv420p) · 9.1 MB |
| 녹화일 · 환경 | 2026-11-16 · Windows 11, 1680×1050(100%) · Python 3.12.4 |
| 조작 방식 | **자동화된 GUI 입력 시연**(사람이 직접 플레이한 영상이 아님) |
| 보낸 입력 | 키 731회, 마우스 클릭 25회 (`input_log.json`) |
| 오류 · 포커스 이탈 | 0회 · 0회 |

## 1. 제작 방식

1. **실행:** 수정하지 않은 `python run.py`를 별도 프로세스로 2번 실행했습니다(두 번째는 기록 유지를 확인하기 위한 재실행).
2. **입력:** Windows `SendInput`으로 키보드·마우스 입력을 보냈습니다. 실제 키보드·마우스와 같은 OS 입력 경로입니다.
   - 입력하기 직전마다 전면 창이 게임 프로세스의 창인지 확인했습니다. 아니면 즉시 중단해 다른 앱에 입력이 들어가지 않게 했습니다.
   - 시험 실행에서 이 안전장치가 실제로 작동해 녹화를 멈춘 적이 있습니다.
3. **판단:** 자동 입력 프로그램은 녹화한 창의 픽셀만 읽어 판단했습니다(`vision.py`).
   - **화면에서 읽는 것:** 보드 칸, 현재 블록, 퍼즐 힌트의 금색 칸
   - **판단 방법:** 놓을 위치는 자동 입력 프로세스 안에서 같은 엔진 함수로 오프라인 계산했습니다(순수 함수, 게임 프로세스와 무관).
   - **퍼즐:** H 키로 게임이 표시한 힌트 2단계의 금색 칸을 화면에서 읽어 목표로 삼고, ← → ↓ ↑/Z 키를 한 번 누를 때마다 화면을 다시 읽어 위치를 확인했습니다.
4. **녹화:** Win32 `PrintWindow`로 게임 프로세스의 창만 캡처했습니다. 다른 앱과 바탕화면은 찍히지 않습니다.
   - **기록 창:** 화면에 실제로 떠 있는 위치 그대로 합성했습니다.
   - **커서:** PrintWindow에는 마우스 커서가 찍히지 않습니다. 매 프레임 실제 커서 위치(`GetCursorPos`)를 기록해 편집 때 그렸습니다.
5. **편집(`compose_video.py`):** 게임 화면은 1:1 픽셀로 복사했습니다(확대·보정 없음). 추가한 것은 다음뿐입니다.
   - 장면 카드 10개
   - 자막
   - 실제로 보낸 키와 클릭 표시(입력 로그 기반)
   - 실제 커서 위치
   - 2배속 구간(총 4.4초 분량, 화면에 "2배속 (편집)" 표시)

### 금지 사항 준수

| 금지 사항 | 준수 여부 |
|---|---|
| 보드·블록·현재 블록·공격량·점수·승패·퍼즐 성공 직접 변경 | 없음. 녹화 스크립트는 게임 프로세스의 객체에 접근할 방법이 없습니다(별도 프로세스). |
| `Player.move/rotate/hard_drop`, `GameApp.key_down` 직접 호출 | 없음. `tetris.gui`는 가져오지(import) 않습니다. `tetris.engine/ai/puzzles`의 순수 함수만 자동 입력 프로세스 안에서 계산용으로 사용했습니다. |
| 미리 만든 화면·상태 삽입 | 없음. 모든 게임 화면은 녹화 원본 프레임입니다. 보드는 매 게임 빈 상태(퍼즐은 게임이 생성)에서 시작했습니다. |
| 사람이 하지 않은 플레이를 "직접 플레이"로 표기 | 없음. 첫 카드와 모든 프레임 하단에 "자동화된 GUI 입력 시연"을 표시했습니다. |

### 그 밖의 확인
- **검은 화면:** ffmpeg `blackdetect` 결과 0건입니다.
- **4초 이상 거의 정지한 화면** (`freezedetect`): 0:00 첫 안내 카드, 1:41 난이도 버튼 클릭, 3:19 기록 창 표시, 3:28·3:33 재실행 카드와 기록 화면. 모두 의도한 정적 화면입니다. 녹화 원본의 최대 프레임 간격은 0.2초였습니다.
- **캡처 프레임 수:** 평균 초당 22.7장입니다. 어려움 AI가 계산하는 동안에는 게임 창의 응답이 늦어 PrintWindow도 늦어졌습니다. 그런 시점은 건너뛰고, 실제 캡처 시각에 맞춰 30fps로 출력했습니다.
- **창이 닫힐 때의 멈춤:** 창이 닫히는 순간(장면 8, 3:25)에는 마지막 프레임이 약 0.2초 반복됩니다.

## 4. 편집 중 수정한 자막 (게임 화면은 수정하지 않음)

`caption_fixes.json`에 원본 로그 시각과 이유를 함께 기록했습니다.

- **장면 5:** 결과 화면을 보여 주려고 "P1이 Space만 눌러 일부러 Top-out"하는 단계를 준비해 두었습니다. 그런데 P1은 그 전에 이미 AI의 방해 줄 4줄을 받고 실제로 Top-out했습니다. 미리 정해 둔 자막이 사실과 달라서 "AI가 보낸 방해 줄 4줄을 받은 뒤 블록이 천장까지 쌓여 Top-out"으로 바꿨습니다.
- **글꼴에 없는 글자:** `☰` 기호가 글꼴에 없어 자막에서 `[기록]`으로 표시했습니다.
- **배속 문구:** 실제 배속이 아닌 구간에서는 "(2배속 편집)" 문구를 표시하지 않습니다.

## 6. 촬영하지 못했거나 한계가 있는 부분

- **사람의 직접 플레이 아님:** 모든 조작은 OS 수준 자동 입력입니다. 자동 입력의 실력은 사람 수준이 아니어서 1인용·대전 보드에 구멍이 생긴 장면이 있습니다. 실제 입력 결과이므로 그대로 두었습니다.
- **`python run.py` 명령 화면:** 터미널은 녹화하지 않았습니다. 다른 창이 함께 찍히는 것을 막으려고 게임 창만 녹화했기 때문입니다. 장면 카드에 실행 명령을 적고, 실행 직후의 첫 화면부터 녹화했습니다.
- **한글 입력기(IME):** 한글 IME가 켜진 상태에서의 키 입력은 이 영상으로 확인하지 않았습니다.
- **T-Spin과 Combo/B2B:** 일반 대전 중의 T-Spin과 Combo/B2B 보너스는 영상에 나오지 않습니다. T-Spin은 퍼즐에서만 시연했습니다.

## 7. 다시 만들기

```bash
python docs/real_demo/record_real_demo.py <원본폴더>        # 약 4분, 그동안 키보드·마우스 사용 금지
python docs/real_demo/compose_video.py <원본폴더> 테트리스_레벨3_실제플레이_시연영상.mp4 docs/real_demo/caption_fixes.json
```

`record_real_demo.py`는 `save/records.json`이 이미 있으면 시작하지 않습니다. 녹화를 마친 뒤의 기록 파일은 `records_after_demo.json`으로 옮겨 두었습니다.
